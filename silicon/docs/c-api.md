# C API

SILICON exposes a versioned synchronous C ABI through `crates/silicon-c-api`.
Include [`silicon.h`](../crates/silicon-c-api/include/silicon.h), link the
`silicon_c_api` shared library, and check `silicon_c_api_version()` before
depending on optional additions. ABI version 1 returns integer status codes;
`silicon_last_error` copies a thread-local diagnostic into caller-owned memory.
Incompatible function signatures, public structure layouts or status semantics
require a C ABI version increment; new functions may be added without changing
existing version-1 behavior.

The opaque handles cover a device/framebuffer, translated SPIR-V pipeline,
typed vertex/index/uniform buffers, RGBA8 textures, and command buffers. A C
caller can record a render pass, bind resources, draw, submit synchronously and
copy the resulting RGBA8 framebuffer. Binding retains shared resource
references, so a resource handle can be destroyed after recording; the command
buffer keeps the resource alive through submission.

The first ABI version intentionally exposes a small graphics subset:

- SPIR-V 1.0 modules are limited to 1 MiB each and must fit SILICON's documented
  graphics subset.
- Pipelines select front-face culling, back-face culling or none; all other
  state uses SILICON's default pipeline values. Draws use triangle lists.
- Vertex, index, uniform and texture sizes use the existing Rust API limits.
- Textures are single-level RGBA8 and use the default sampler.
- The framebuffer is a single-sample RGBA8 target with fixed dimensions.
- Submission is synchronous; there are no queues, callbacks or host GPU calls.

Pointers passed to creation and copy functions must address valid aligned
memory for their stated lengths. Handles must be live values returned by the
matching constructor and destroyed exactly once. Null handles are rejected;
null destroy handles are ignored. The API catches Rust unwinds at ordinary
entry points when the library is built with unwind panics. Invalid or stale
non-null pointers violate the caller's safety contract. Calls that mutate a
device or command buffer, and calls that destroy any handle, must be serialized
against other access to those same handles.

Build and run the standalone C client, which submits a textured SPIR-V triangle
and saves the CPU-rendered result as `output/c_api_triangle.ppm`:

```sh
sh crates/silicon-c-api/scripts/test.sh
```

![Triangle generated by the C API smoke client](../assets/screenshots/c_api_triangle.png)

This is a stable C ABI subset. It is not a Vulkan loader or a Vulkan-compatible
implementation; compatibility work remains a separate milestone.
