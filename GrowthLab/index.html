The unit of progress is a changed file with inspectable evidence. GrowthLab keeps the goal, baseline, constraints and check contract together.

  1. 01

    Freeze the starting point

    Import a local Git product with a reviewed, committed growthlab.yaml. Every competitor receives the same source commit and permissions.

    One contract
  2. 02

    Explore three implementations

    Run declared replay proposals as actual edits in isolated Git worktrees. Native-agent battle verification is the next execution gate.

    Separate worktrees
  3. 03

    Keep the evidence

    Run real configured commands on immutable candidate snapshots. Inspect diffs, logs, source previews, failures and SHA-256 seals.

    Observed checks
  4. 04

    Choose what reaches your product

    Select an eligible sealed candidate. Preview its apply, export its patch, or explicitly copy it to a clean baseline. You own the commit and deployment.

    Explicit delivery

Your product. Your boundaries.

An experiment
is not permission
to publish.

Local by default

Files, worktrees and evidence stay on your machine.

Rust, SQLite and a loopback dashboard. Optional provider proposals have a separate authorization boundary; the bundled replay needs no agent API key.

Permission before implementation

Allowed paths are a contract.

Denied paths take precedence. Credentials and protected directories are refused. Configured validation uses OS confinement, with no unrestricted fallback.

Provenance before persuasion

Observed is not measured.

The current demo records simulated proposals, observed checks and untested growth outcomes. Private-by-default offline reports preserve that distinction.
