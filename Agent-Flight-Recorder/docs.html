01

Overview

A local evidence pipeline, not a chat exporter.

Agent Flight Recorder turns locally exposed coding-agent traces into a canonical, append-only timeline. Native records keep their provenance; calls and outcomes are correlated into logical attempts; snapshot boundaries produce code evolution; gaps remain visible when proof is unavailable.

Core rule

Unavailable evidence is null, unknown, or a first-class gap—not an inferred narrative.

Safe first run

Begin inside the synthetic sandbox.

The deterministic demo creates two compatible-agent flights in .flight-recorder-demo. It performs no native-source scan, accepts no live hook ingestion, forces masking, and requires no provider account or API key.

agent-flight-recorder demo --reset

Open http://127.0.0.1:4174. If that port is occupied:

ALTERNATE PORT

03

Privacy boundary

Local-only is a runtime boundary, not permission to publish evidence.

  • NetworkLoopback bind; untrusted Host and mutating cross-origin requests are rejected.
  • OutboundNo telemetry, analytics, cloud database, or remote exporter.
  • IngestionCredential masking is the default; strict mode also omits raw native records.
  • StorageNormalized payloads, raw envelopes, and snapshot blobs use AES-256-GCM.
  • KeysmacOS Keychain, explicit AFR_STORE_KEY, or a private adjacent key file.
Do not publish a recorder store or bundle.

It can still contain prompts, source, command text, paths, and identifiable metadata. Indexed timestamps, kinds, summaries, commands, paths, and correlations remain plaintext.

Run the repository privacy gate before every public commit:

PUBLICATION CHECK 
npm run privacy:check
04

Evidence model

Events stay native. Operational meaning is correlated alongside them.

Every canonical event has a stable ID, session, sequence, timestamp, kind, actor, status, summary, optional command or path, correlation IDs, normalized payload, and optional raw evidence.

promptreasoningresponsetool terminalfiletestpermission tokenretrygapcontext lifecycleerrorartifact

Assurance labels

Exact
Captured synchronously around a provider hook.
Best-effort
Observed from an append-only source where timing cannot prove a true pre-state.
Explicit
A provider reported the permission decision directly.
Executed / inferred
A correlated tool completed after a request; execution is proven, manual approval is not.
Unknown / unresolved
No trustworthy result arrived inside the bounded window.

Retries are derived only when an identical invocation follows an observed failed or blocked attempt in the same turn or within five minutes. Repeated success is not mislabeled as retry behavior.

Providers

Five capture surfaces, one operational vocabulary.

Codex

All 11 official lifecycle hooks. Incremental transcript reads remain a version-tested historical backfill, not a stable API.

OpenCode

Uses opencode db path before a version-tested default fallback, then imports the internal SQLite database and WAL read-only. The schema is not a guaranteed API.

Claude Code

All 33 documented official hook events. The local hook adapter does not expose hidden reasoning or complete token/cost telemetry.

Cursor

All 21 documented local IDE/CLI hook events. Cloud agents expose a smaller subset.

06

Hook configuration

Preview first. Apply only when the merge is understood.

The managed installer structurally merges existing JSON, deduplicates recorder handlers, and creates a timestamped backup. Without --apply, every install, uninstall, rollback, and retention command is a dry run.

CODEX / PREVIEW THEN APPLY 
node build/server/cli.js install-hooks \
  --provider=codex \
  --scope=user \
  --data-dir="$PWD/.flight-recorder"

# Apply only after reviewing the preview:
node build/server/cli.js install-hooks \
  --provider=codex \
  --scope=user \
  --data-dir="$PWD/.flight-recorder" \
  --apply

Recorder hooks return success by default even after a capture failure and never emit provider decisions. Provider timeout semantics differ. Hooks run with the local user’s permissions, so generated commands must be reviewed.

07

Portable bundles

Carry one flight as an authenticated encrypted archive.

Bundles contain one detailed session, ordered canonical events, snapshot provenance, and referenced content blobs. The default format uses gzip, scrypt key derivation, AES-256-GCM, a per-bundle salt, and an archive digest.

EXPORT + IMPORT 
export AFR_BUNDLE_PASSPHRASE='use-a-long-local-passphrase'
node build/server/cli.js export \
  --session='codex:SESSION_ID' \
  --out=./flight.afr

node build/server/cli.js import \
  --in=./flight.afr \
  --data-dir=./restored-recorder
A bundle is sensitive evidence.

Do not commit it. Keep the passphrase outside shared shell scripts and committed environment files.

09

Loopback API

Query replay evidence without exposing a remote service.

GET/api/health

Readiness, policy, source, snapshot, gap, call, permission, and heartbeat health.

GET/api/overview

Counts, storage policy, schema version, and source summary.

GET/api/sessions

Lightweight recorded-flight list projections.

GET/api/sessions/:id/events

Ordered timeline projections with a bounded limit.

GET/api/events/:id/evolution

Snapshot assurance, boundaries, and bounded unified diff.

GET/api/compare?left=:id&right=:id

Canonical metrics, kinds, failures, gaps, and files.

POST/api/scan

Manual native scan; rejected inside the public demo sandbox.

SSE/api/stream

Live local update notifications.

Responses include request IDs. Unexpected internal failures are logged locally while clients receive a bounded error without implementation details.

10

Limits

Evidence completeness is provider-bound.

  • Provider-private reasoning, non-emitted callbacks, and unavailable permission decisions cannot be reconstructed.
  • Codex, Claude Code, and Cursor callback delivery must be validated on an opted-in installation of those products.
  • Evidence columns are encrypted, but indexed metadata remains plaintext; full-page SQLCipher is not provided.
  • Parallel identical actions without call IDs can remain temporally ambiguous.
  • This is a single-user loopback tool. Remote access and multi-user authentication are outside the threat model.

For port conflicts, store-key errors, reconnecting consoles, browser installation, and locked databases, see the full troubleshooting guide.
