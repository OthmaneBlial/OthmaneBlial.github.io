Early alpha · loopback-tested

A browser terminal for the Linux machines you already run.

AetherTerm is a small self-hosted server plus an agent you place on each machine you administer. The agent opens an authenticated WebSocket out to the server, so the browser receives only the operator's own PTY sessions. There is no inbound listener to add on the target and no SSH protocol involved.

Run it locally Read the quickstart Source on GitHub
Not ready for network deployment. The documented run uses plain ws:// on loopback. A TLS option exists and has been tried locally with a temporary certificate, but public HTTPS/WSS has not been validated. Keep the server on 127.0.0.1 while the security roadmap is implemented.

What exists today

An alpha you can inspect, not a release you can deploy

Everything below is implemented in this repository and covered by local tests or Linux CI runs. Nothing here is a production-readiness claim.

  • Server

    A Python FastAPI service with two WebSocket endpoints: /ws for the browser console and /client for enrolled agents.

  • Agent

    A Python agent that opens a real /bin/bash PTY on request and reconnects after a temporary outage with bounded backoff.

  • Console

    A bundled xterm.js interface listing enrolled devices and their connection state, with independent terminal tabs, resize, Unicode paste and a toolbar Ctrl+C action.

  • Access control

    Operator password sign-in with a cookie session, plus per-device credentials stored in owner-readable files that the server can rotate and revoke.

  • Session model

    Each browser session owns only the PTYs it starts. Shells close on disconnect and no command history or session recording is stored by default.

  • No external assets

    The terminal UI ships inside the Python package. The page derives its WebSocket URL from its own origin and needs no CDN connection.

Architecture

Who talks to whom

The agent initiates the connection. Nothing in the browser can reach a machine that is not enrolled on that server, and every active device belongs to the single operator account.

  1. 01

    Browser

    The operator signs in and opens /web/. The console holds an authenticated WebSocket to the server and shows only its own sessions.

  2. 02

    Server

    One process is authoritative for live WebSocket and PTY state. Durable operator and device identities survive a restart; live shells do not.

  3. 03

    Agent

    Each enrolled device holds its own credential file and dials out to /client. A rotated or revoked credential stops authorizing connections.

  4. 04

    PTY

    A shell runs as the agent's own operating-system user. AetherTerm does not sandbox that shell or elevate its privilege.

AetherTerm does not implement SSH and makes no SSH-compatibility claim. Documented differences with existing terminal gateways are tracked, deliberately unmeasured, in the positioning notes.

Quickstart

From a checkout to a real shell

Targets Python 3.13 and a POSIX shell. The sequence below runs one server and one agent on the same machine over loopback — a demonstration, not an Internet deployment.

The demo starts a real server and agent on a random loopback port and prints a one-time operator password. Select demo-agent, then press Ctrl+C to stop both processes and delete the temporary identities. It never touches your normal AetherTerm configuration.

Keep the identities instead

Then open http://127.0.0.1:8001/web/, enter the operator password and choose local-agent. Full rotation, revocation and shutdown steps are in the quickstart; the installed entry point binds to 127.0.0.1 only.

Keep credential files out of Git, screenshots and command arguments. Never run the agent as root merely to make a command work.

Evidence

What is verified, and what is still open

CI results support only their tested matrix. A passing build is not a device claim, a deployment claim or an adoption claim.

AreaVerified todayStill open
Shell relay Two independent PTYs, explicit close, browser disconnect, agent SIGTERM/SIGINT and server restart have integration tests. Chrome showed Unicode, ANSI colours, less, Ctrl+C and resize; Chromium, Firefox and WebKit each complete a real agent/PTY browser journey in CI. Remaining graphical terminal interactions and real deployment validation.
Browser access Password login, cookie session, same-origin WebSocket and a negative cross-browser injection test. Expiry and revocation under load, external deployment, independent security review.
Agent identity Per-device credential-file enrolment, rotation and revocation tested locally. Remote encrypted transport plus Linux installation and operating guidance.
Transport Remote cleartext is refused in code. Direct TLS and a local Caddy HTTPS/WSS proxy test with certificate validation passed. Public certificate, external network and graphical browser validation.
Packaging A wheel installed in clean Python 3.13 environments served its bundled UI and completed an authorised PTY round trip on macOS and Ubuntu 24.04 CI. The non-root container, dependency scans, three browser journeys and a Linux x86_64 agent binary with a real PTY passed in CI. Publicly tested downloads and a verified release artifact.
Layout The live shell has no horizontal overflow at 320, 375, 390, 768 or 1280 px in CI, and two real terminal tabs switch with arrow, Home and End keys. Physical touch input, a human screen-reader review and clipboard behaviour outside Chrome.

Not yet measured anywhere: a remote HTTPS/WSS deployment on a public host, a published release download, a hands-on comparison with other terminal gateways, and any target-user study. The roadmap holds the work and the evidence each item still needs.
